## 4. 資料模型

### 4.1 `CameraProfile` 欄位變更（其餘欄位同 0.1 §4.1）

| 欄位 | 變更 | 型別 | 說明 |
|---|---|---|---|
| `themeID` | **移除** | — | 由 `style` 取代，讀舊檔時轉換（§4.3） |
| `largestUnit`、`smallestUnit` | **移除** | — | 由 `displayUnits` 取代，讀舊檔時轉換（§4.3） |
| `style` | **新增** | `OverlayStyle` | 見 §4.2 |
| `displayUnits` | **新增** | `Set<DisplayUnit>` | 要顯示的天數單位，任意非空子集合（§4.5）。預設 `[.day]` |
| `position` | **改型別** | `OverlayPlacement` | `.anchor(OverlayPosition)`（九宮格）或 `.custom(x: Double, y: Double)`，x、y 為疊字框中心點佔照片寬、高的比例，範圍 0～1（A-1） |
| `showFilmDate` | **新增（1.1.0）** | `Bool` | 底片日期戳記開關（FR-11.7）。預設 `false`；舊檔缺欄位時用預設 |
| `dayCountFormat` | **新增（1.3.0，#582）** | `DayCountFormat` | 只勾天時的寫法：`ordinal`（第 N 天）／`plain`（N 天）／`dayN`（Day N）／`dDay`（D-Day），預設 `ordinal`；缺欄位或未知字串一律退回預設，不讓整個設定檔解碼失敗（U-11） |
| `filmDateCorner` | **新增（1.1.0）** | `FilmDateCorner` | `topLeading`／`topTrailing`／`bottomLeading`／`bottomTrailing`，預設 `bottomLeading`；缺欄位或未知字串一律退回預設，不讓整個設定檔解碼失敗 |

設定檔在 `profiles.json` 陣列中的**順序就是顯示順序**（管理設定檔、頂部選單都照這個順序）。

**不變條件**（持久化層強制，違反時 `add`／`update` 拒絕）：

- 0.1 不變條件 1～3 不變
- 0.1 不變條件 4（單位必須在同一軌道）**廢除**，改為：`displayUnits` 不得為空
- 0.1 不變條件 5 **廢除**：`useAgeWording` 與 `displayUnits` 互不限制；舊檔照常有效，不需遷移
- 新增：`style.sizeScale` 介於 70 與 160 之間，且是 5 的倍數
- 新增：`position` 為 `.custom` 時，x、y 皆介於 0 與 1 之間（含）
- 新增：`style.textColor` 與 `style.outlineColor` 的 RGB 各分量介於 0 與 1 之間；alpha 介於 0.05 與 1 之間（含），存檔量化為 8 bit。讀檔遇到低於 0.05 的 alpha（只可能是手改檔案）提高到最小可存值 13/255 並採用該筆，不丟棄
- 新增：`style.strokeWidth` 介於 1 與 6 之間、`style.boxPadding` 介於 0 與 24 之間（含）；`style.autoOutlineOpacity` 介於 0.05 與 1 之間（含），存檔量化為 8 bit。寫入時超出範圍一律拒絕；讀檔遇到超出範圍的值（只可能是手改檔案）夾回範圍內並採用該筆，不丟棄
- 新增：`style.shadowOffsetX`、`style.shadowOffsetY` 介於 −8 與 8 之間，`style.shadowBlur` 介於 0 與 16 之間（含），陰影關閉時也檢查；`style.shadowColor` 同 `textColor` 的色彩規則（alpha 0.05～1，存檔量化為 8 bit）。寫入與讀檔的處理同上一條

讀檔時遇到**未知的 `fontID`**（例如日後移除某字型），改用 `sfRounded` 並採用該筆，不丟棄。

### 4.2 `OverlayStyle`

| 欄位 | 型別 | 預設 | 值域 |
|---|---|---|---|
| `fontID` | `OverlayFontID` | `pingFang` | PRD-0.3 §4.1 |
| `textColor` | `OverlayColor`（加上 `Codable`；不透明存 `#RRGGBB`，半透明存 `#RRGGBBAA`，讀取兩種都接受，`#RRGGBB` 視為 alpha 100%） | `#FFFFFF` | 任意 sRGB 色，alpha 5%～100% |
| `outline` | `OverlayOutline` | `.none` | `none`／`stroke`／`box`（舊值轉換見 §4.3） |
| `outlineColor` | `OverlayColor?`（格式同 `textColor`） | `nil` | `nil` ＝ 自動（FR-10.6）；有值則照該色，alpha 5%～100%。底框的透明度就是外框色的 alpha |
| `autoOutlineOpacity` | `Double` | `1` | 0.05～1；只在 `outlineColor` 為 `nil`（自動）時作為自動外框色的 alpha |
| `strokeWidth` | `Double`（pt，17pt 字級基準） | `2` | 1～6；描邊露在字形外的寬度。選其他外框時保留 |
| `boxPadding` | `Double`（pt，17pt 字級基準） | `12` | 0～24；底框水平內距，垂直內距 ＝ 水平 × 0.5。選其他外框時保留 |
| `showsShadow` | `Bool` | `true` | 陰影開關；關閉時保留下列參數 |
| `shadowColorSource` | `OverlayShadowColorSource` | `.custom` | `custom`＝用 `shadowColor`；`textColor`＝用文字色的 RGB，改文字色時跟著變（光暈） |
| `shadowColor` | `OverlayColor`（格式同 `textColor`） | `#00000099` | alpha 即陰影透明度（5%～100%），無論顏色來源都使用；RGB 只在 `custom` 時使用，跟隨文字色期間保留 |
| `shadowOffsetX`、`shadowOffsetY` | `Double`（pt，17pt 字級基準） | `0`、`2` | −8～8；Y 正值向下 |
| `shadowBlur` | `Double`（pt，17pt 字級基準） | `4` | 0～16 |
| `sizeScale` | `Int`（百分比） | `100` | 70～160，步進 5 |

預設值等同 0.1 的「經典白」（字型預設見 PRD-0.3 §4.1）。

### 4.3 舊檔轉換

讀到 0.1 格式（有 `themeID`、`largestUnit`、`smallestUnit`；`position` 是字串）時，轉換後採用，並在下次寫入時存成新格式。**不得丟棄設定檔**。

**樣式**：

| 0.1 `themeID` | 字型 | 顏色 | 外框 | 外框顏色 | 陰影 | 與 0.1 的差異 |
|---|---|---|---|---|---|---|
| `classicWhite` | SF Rounded | `#FFFFFF` | 無 | 自動 | 柔和 | 無 |
| `retroOrange` | SF Mono | `#FF9500` | 無 | 自動 | 柔和 | 陰影略淡、略大 |
| `filmStrip` | SF Mono | `#FFFFFF` | 半透明底框 | 自動 | 無 | 底框不透明度 45% → 50% |
| `minimalDark` | SF Pro | `#1C1C1E` | 半透明底框 | 自動 | 無 | 底框不透明度 70% → 50%，字重 semibold → bold |
| `softPink` | SF Rounded | `#FF6B9D` | 細描邊 | 自動 | 柔和 | 陰影略深 |

上表的「半透明底框」存成 `box`＋`autoOutlineOpacity` 50%、「細描邊」存成 `stroke`＋寬 2。

**外框（舊格式）**：`outline` 讀到舊值時轉換後採用，下次寫入存成新格式。**畫面與升級前一致，不得丟棄設定檔**。

| 舊 `outline` | `outline` | 參數 | 外框色 alpha |
|---|---|---|---|
| `thinStroke` | `stroke` | `strokeWidth` 2 | 不變 |
| `thickStroke` | `stroke` | `strokeWidth` 4 | 不變 |
| `translucentBox` | `box` | `boxPadding` 12 | × 50%：有 `outlineColor` 則乘在該色 alpha；自動（`nil`）則存在 `autoOutlineOpacity`，保留「自動」。乘完低於 0.05 時提高到 0.05 |
| `solidBox` | `box` | `boxPadding` 12 | 不變 |

alpha 存檔量化為 8 bit，50% 存成 128/255；烘焙與預覽的像素實測與升級前完全相同（`OverlayRendererOutlineMigrationTests`）。

**陰影（舊格式）**：沒有 `showsShadow` 的樣式是舊格式，讀 `shadow` 的舊值轉成對應的快速預設參數後採用，下次寫入存成新格式，不再寫 `shadow`。**不得丟棄設定檔**；未知的 `shadow` 值與改版前一樣解碼失敗。

| 舊 `shadow` | `showsShadow` | 顏色來源 | `shadowColor` | X, Y | 模糊 |
|---|---|---|---|---|---|
| `none` | 關 | 自訂 | `#00000099` | 0, 2 | 4（保留柔和參數，打開即為柔和） |
| `soft` | 開 | 自訂 | `#00000099`（0.6＝153/255） | 0, 2 | 4 |
| `hard` | 開 | 自訂 | `#000000BF`（0.75 → 191/255） | 2, 2 | 0 |
| `glow` | 開 | 文字色 | `#000000E6`（0.9 → 230/255，只用 alpha） | 0, 0 | 8 |

預設值都落在 8 bit 上，所以讀舊檔不會觸發回寫。烘焙與預覽實測：文字不透明時所有組合與升級前逐 byte 相同；`hard` 配半透明文字也相同。**例外**：`glow` 配半透明文字時，Core Graphics 以浮點計算陰影 alpha，沒有任何 8 bit 值等於 0.9，部分像素差 1/255（`OverlayRendererShadowMigrationTests`）。

**單位**：`(largestUnit, smallestUnit)` 轉成兩者之間（含）的軌道單位，例如 `(year, day)` → `[.year, .month, .day]`、`(week, day)` → `[.week, .day]`。轉換後的輸出文字與 0.1 **完全相同**（§4.5 的規則保證）。

**位置**：0.1 字串（如 `"bottomTrailing"`）轉成 `.anchor(.bottomTrailing)`。

> **為什麼樣式接受些微差異（A-2）**：若要像素一致，得讓每個舊主題保留自己的專屬參數，等於在新模型裡藏一套舊主題系統。差異都在陰影、底框濃淡，不影響辨識度，而使用者升級後可以自己調。

### 4.5 天數單位的計算與文字（取代 0.1 FR-2.7～2.10、FR-2.12～2.14 的軌道規則）

使用者勾選 `displayUnits`（年、月、週、天的任意非空子集合），輸出依以下規則產生。**本節規則對 0.1 的 8 種合法組合輸出與 0.1 完全相同**——唯一例外是 U-7 的全為 0：沒有勾天的組合不再輸出 `0 天`，這不是回歸。

| # | 規則 |
|---|---|
| U-1 | 單位一律依 年 → 月 → 週 → 天 的順序輸出 |
| U-2 | **只勾天**：輸出 `第 {n} 天`（序數，0.1 FR-2.13）。`n` 套用起算規則。寫法非 `ordinal` 時見 U-11 |
| U-3 | **沒勾年也沒勾月**（只有週、或週＋天）：剩餘天數 `r = n`（**套用**起算規則的 +1），週 = `r / 7`，天 = `r % 7` |
| U-4 | **有勾年或月**：依序取整——勾年時先算從起始日起滿幾年，錨點移到該週年日；勾月時再算從錨點起滿幾個月，錨點再移過去；剩餘天數 `r` = 錨點到拍攝日的曆法天數（**不套用** +1，同 0.1）。勾週時週 = `r / 7`、`r %= 7`；勾天時天 = `r` |
| U-5 | 沒勾的單位不拆：例如只勾年和天，年以下全部算成天（「1 年 64 天」） |
| U-6 | 月份加法遇到不存在的日期時，夾到該月最後一天（Foundation 原生行為，同 0.1 §7.1 的 2/29 規則） |
| U-7 | 值為 0 的單位省略；全部為 0 時，以**勾選的最小單位**（天 < 週 < 月 < 年）輸出 `0 {單位}`，例如只勾年為 `0 年`（加「歲」為 `0 歲`）、年＋月為 `0 個月`、只勾週為 `0 週`；有勾天時仍是 `0 天` |
| U-8 | **連接詞**：勾選**恰好兩個單位且不含年**時，兩節之間用「又」（`61 週又 3 天`、`14 個月又 5 天`、`14 個月又 3 週`）；其餘一律用半形空格（`1 年 2 個月`、`1 年 5 個月 3 週 2 天`）。判斷依據是**勾選**的單位數，不是實際非零的節數，同一組設定格式固定（0.1 FR-2.14 的精神） |
| U-9 | `useAgeWording` 開啟時「年」印成「歲」（0.1 FR-2.9） |
| U-10 | **倒數**（起始日在拍攝日之後，判斷依據 `rawDayDifference < 0`）：以「拍攝日 → 起始日」的日曆差照 U-1～U-8 拆解，前綴 `還有 `，例：`還有 3 個月又 4 天`、`還有 13 週又 5 天`、`還有 1 年 3 個月`。不套用計數規則；`useAgeWording` 開著也一律寫「年」；只勾天，或勾選的單位全部為 0（例：只勾年、還有 96 天）時輸出 `還有 N 天`，不輸出 `還有 0 年` |
| U-11 | **寫法**（1.3.0，#582）：只勾天時依 `dayCountFormat` 輸出——`ordinal` `第 {n} 天`、`plain` `{n} 天`、`dayN` `Day {n}`（皆套用起算規則）；`dDay` **不套用起算規則**，以原始日差 `d` 輸出：`d > 0` 為 `D+{d}`、`d = 0` 為 `D-Day`。倒數時：`ordinal`／`plain` `還有 {N} 天`、`dayN` `{N} days to go`、`dDay` `D-{N}`。勾了週、月或年時寫法不套用，一律照 U-1～U-10 |

基準情境（0.1 §3.2）：起始日 `2025-01-15`、`dayOne`、拍攝 `2026-03-20`，`n = 430`。

| 勾選 | 輸出 | 與 0.1 |
|---|---|---|
| 天 | `第 430 天` | 相同 |
| 週、天 | `61 週又 3 天` | 相同 |
| 月、天 | `14 個月又 5 天` | 相同 |
| 年、月 | `1 年 2 個月` | 相同 |
| 年、月、天 | `1 年 2 個月 5 天` | 相同 |
| 年、天 | `1 年 64 天` | 新組合 |
| 年、月、週、天 | `1 年 2 個月 5 天`（週為 0 省略） | 新組合 |
| 月、週 | `14 個月`（週為 0 省略） | 新組合 |

> **為什麼開放任意組合**：0.1 讓週自成一軌，是認為「1 年 2 個月 3 週」不是自然說法。改成勾選框後，限制組合會讓勾選被自動取消或鎖住，使用者會以為壞了。每種組合都有確定的算法與正確結果，要不要這樣寫交給使用者。
